# Public status verification

The read-only public capture contains 235 observables after the dashboard's
input and Foundations exclusions. Its statuses are 38 `theorem`, 20
`exectheorem`, 75 `conditional`, 9 `computation`, 53 `open`, 23 `diagnostic`,
8 `frozen`, 8 `rejected` and one `premise`. Thus 58/235, or 24.7%, count as
completed under the page's own rule.

The identifier set equals the original captured catalogue. Exactly the
eight reviewed rows changed status, each from `computation` to `exectheorem`.
The scientific recommendation and its original 50/235 baseline remain in
`results.json`; they are not rewritten as if this package published the
website. `live_status.json` holds the separate public capture, its asset URL
and SHA-256, all 235 minimal rows and the eight full selected rows. A literal
parser reads the public JavaScript data without evaluating it.

The status transitions are applied, but two descriptions require
correction. The joint screen-reference title says that the untouched
reference alone is unchanged, while its summary and explanation
attribute different coherences to that reference. The integer-lift value
and summary separate the 99.7% diagnostic, while the explanation
assigns Standard Model hypercharge and the summary does not separate
imported large-run counts from the executed finite reference. The finite
proofs do not support those broader readings.

`verify_live.py` checks the exact identifier and status differences, counts,
detail/summary consistency and the literal outstanding wording. It binds the
original reviewed proposal and all its scientific source receipts. Its
output supplies replacement summary and explanation text from that proposal
for both rows, with no further status change or score increase. A changed
public text requires another review; the verifier fails rather than assuming
the same corrections apply.

This verification makes no website write, identifies no external editor,
accepts no physical completion gate and adds no empirical observation.
