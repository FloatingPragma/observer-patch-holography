# Instructions for work under openwave/

These instructions apply to every agent working in this directory and its
descendants. They turn the lessons of PR #723 into required design and review
checks. Read [CAUTIONS.md](CAUTIONS.md) first. The mission remains to establish
physical descriptions from observers' records on a specified native process
and meet OpenWave's actual row criteria.

**Before any upstream submission, complete the mandatory
[SUBMISSION_CHECKLIST.md](SUBMISSION_CHECKLIST.md) against the exact outgoing
version.** Retain an evidence-linked, reviewed copy with the submission. An
unchecked, failed or unresolved applicable item blocks submission; caveats,
passing arithmetic and same-group approval do not waive it. Apply the
checklist's explicit scope rules for registration or administrative work.

## Start from the evidence and the assigned scope

1. Read the relevant row's `README.md`, `THEOREMS.md`, `STATUS.json` and recent
   review/ledger, plus [ESTABLISHED.md](docs/ESTABLISHED.md) and
   [CANDIDATES.md](docs/CANDIDATES.md). Identify existing results, their
   hypotheses and the precise unresolved obligation before designing work.
2. For row research or filing, apply [DELIVERABLE.md](docs/DELIVERABLE.md),
   [FRAMEWORK.md](docs/FRAMEWORK.md), [ACCEPTANCE.md](docs/ACCEPTANCE.md) and
   [STRATEGY.md](docs/STRATEGY.md). Read the actual upstream criterion and latest
   applicable decision. Older summaries and local expected marks cannot
   override an explicit maintainer decision.
3. Respect current assignments, owner pauses and concurrent workers. Keep new
   experiments in their own row `work/<date>_<party>_<name>/` directory; keep
   reviews separate. Preserve sealed packets and other workers' edits.

## Before a claimed experiment

Write these items into the design/task and its prospective record:

- The exact row clause and candidate, with law, state domain, preparation,
  scheduler/controller, memory, read/reset operations, decoder and outcomes.
- Which observers hold which records, the observable computed from those
  records, and the map to the proposed physical interpretation. Hidden state
  may be used for a separately labelled audit, not smuggled into the reader.
- Every supplied ingredient, measured input and calibration, and what remains
  to be predicted after those inputs are fixed.
- What the native law contributes to the **target property** beyond identities
  of the alphabet, geometry, reference and reader.
- A representable falsifying outcome and a control that tests that property
  with the same observer/readout. Preserve the relevant symmetry when testing
  whether the law contributes more than geometry already guarantees.
- Separate planted-effect/integrity checks and a list of identities that earn
  no emergence credit. Corrupted records cannot substitute for a scientific
  alternative law.

If the target property is guaranteed by the declaration or survives the relevant
alternative law, narrow the claim or redesign the test. Continue useful local
research, but do not present that property as ready for a row award. Disclosing
an assumption does not by itself qualify a claim for partial credit.
Calling a row static does not waive M10's own-process requirement. Read the
row text together with the column's admission terms; another column's award
cannot replace evidence for this candidate's mechanism.

Hash source, inputs, gates and controls before the claimed confirmatory run and
record the order in the ledger. Disclose prior pilots and known results.
Replaying an already discovered result with newly written gates is reproduction,
not prospective discovery. Preserve original gates and failures when amending.

## Apply the specific PR #723 checks

- **Charge:** integer states/currents and equivalent homology bookkeeping do
  not derive quantization. Test law-selected units or another review-supported
  route in a domain allowing meaningful alternatives. State density limits,
  background ambiguity and counterexamples; never generalize the follow-up's
  `0 ≤ Q ≤ 12` unit result to every integer load.
- **Rest energy:** require actual dynamical selection/holding/return of the
  localized state **and** a second falsifiable energy use: separated-copy
  additivity **or** an unanchored prediction compared with measurement. Retain
  lower modes and the approximately 2.45085 keV separated-pair anomaly. Declare
  the clock and composition convention; do not equate a transfer eigenray,
  decay rate or additive modular statistic with physical rest energy without
  the supporting operational dictionary.
- **Rotation:** test an appropriate symmetry-preserving competing law.
  Covariance half-turn return alone is insufficient. For dynamical antipodal
  identification, retain directional information and an oriented reader; an
  even projection or vacuum erasure earns no credit. For the coherent route,
  measure the full-turn sign/two-turn return through branch interference with
  finer turns. A planted phase only tests sensitivity. Preserve the review's
  alternatives; do not impose a full exchange theorem on every narrower claim.

Every PR #723 follow-up must explicitly answer: what could falsify each result;
which results actually need coherent memory; and how the separated-pair energy
excess is interpreted or left unresolved. Link each answer to evidence or a
specific open obligation. Use [CAUTIONS.md](CAUTIONS.md) for the full rationale.

## Candidate identity and permitted construction

Authorized local candidate construction may proceed without a uniqueness proof
for architecture or a prior column-pin decision. Declare choices and test what
their observer records imply. An installed target law is not evidence that
the native process implements it.

Register changed domains, schedules, controllers, memories or decoders as new
candidates with ancestry, even when the endpoint code is unchanged. Do not
combine clauses from different candidates into a single row/model result
without an implemented, tested common-source join. Preserve the exact reviewed
commit and sealed evidence. Selecting or publishing a new upstream pin follows
the existing owner authorization; local research does not silently move it.

## Execute, review and report within the evidence

1. Keep every outcome, including failures, timeouts, invalid/complement
   outcomes and failed alternatives. Distinguish inconclusive observations
   from falsifications and proof claims from finite samples.
2. Distinguish literal native calls, enumerated branches, matrix powers and
   sampled histories. State and justify any compressed execution.
3. Supply a small inspectable offline headline check with bounded inputs and
   explicit dependencies. Meet the local framework's under-60-second target.
   A small wrapper that fetches and executes a large package is not a small
   review payload. Where an independent check is claimed, state its actual
   independence, including which producer code it imports.
4. Review the headline's scientific meaning as well as arithmetic and custody.
   Try the relevant competing law and write an evidence-linked disposition for
   each criticism. A passing replay does not resolve an objection to the
   physical interpretation.
5. Use existing packet/gate procedures for research changes. A component check
   does not pass full G6. Another Codex worker remains same-group even with a
   separate implementation; never record that review as other-group or owner
   approval. For documentation-only changes, verify factual claims, links and
   the diff without launching unrelated experiments or changing row gates.
6. Report official status first, with its dated decision/source, followed by
   local findings, supplied ingredients and open obligations. PR #723's merge
   and candidate adoption left rows 1, 2 and 7 at 🚧 on 2026-11-15. Verify later
   decisions rather than treating that historical snapshot as permanent.
7. Attribute acceptance only to the maintainers' actual cell decision. Scope
   positive and negative findings to the candidate, observable and hypotheses
   tested. State which theorem or experiment would close the remaining gap.

Prepare reviewable local work within the user's authorization. Follow the
existing owner-controlled upstream workflow; this file grants no new authority
to post comments, push, change pins or award cells.
